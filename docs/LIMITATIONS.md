# LIMITATIONS (final, K7 — v1.0.0)

This file states what CommitProof does not test or cannot conclude. It was started at K0, updated in every sprint, and finalized in K7: no row is PENDING. IDs are stable; `claims.yaml` references them, and a row that states a result carries the id of the claim that backs it. Status values: **DESIGN** (true by design; the sprint in parentheses is the one that added or settled it), **RESOLVED** (no longer applies to the runs named), **OPEN (owner action)** (resolved only by an action outside this repository).

| ID | Limitation | Status |
|---|---|---|
| LIM-01 | **One pinned commit of an alpha system.** Results apply to Multigres `e3cbdbbb0b94453ca2ec43c9c40c05c98ed7bb73` built from source with upstream Dockerfiles. `main` changes daily; the Supabase-hosted alpha may run different code and configuration. | DESIGN |
| LIM-02 | **Not the production topology.** Components run as Docker containers on one bridge network with flags derived from upstream's Kubernetes demo (`deploy/DERIVATION.md`), not under the Multigres Kubernetes operator, not across real availability zones, and with no real network latency unless F7 injects it. | DESIGN |
| LIM-03 | **Shared kernel: no power-loss or page-cache-loss faults.** Killing a container does not lose data the OS has buffered. Failure modes that need an OS crash (e.g. the `remote_write` hazard in upstream's decision log) are unreachable; their absence in results says nothing about them. | DESIGN |
| LIM-04 | **No clock skew.** Per-node skew is impossible for static Go binaries sharing one host clock (ADR-0005). Multigres computes replication lag by comparing the writing pooler's wall clock with the reader's (`heartbeat/reader.go`); behavior under skew (lag-based replica selection, stall detection) is untested. | DESIGN |
| LIM-05 | **Slow disk is emulated.** F4a uses slowfs, a FUSE pass-through on each node's `/data` (ADR-0006, ADR-0022) that delays file `write` and `fsync` requests by the control file's delay; reads, metadata operations, `pg_sockets` (a bind of the plain volume) and multipooler's own I/O (plain volume, other container) are not delayed. It does not model device queueing, partial writes or I/O errors. Every run, also at 0 ms, pays the FUSE overhead with kernel entry/attribute caching disabled (measured in evidence/K3/NOTES.md). The pre-decided F4b fallback was not needed: the baseline cluster on slowfs at 0 ms reached HEALTHY and completed every K3 run (K3). On a CI runner without `/dev/fuse`, `make ci-nemesis-smoke` skips F4a with a SKIPPED-WITH-REASON line (and `cluster up` refuses to start, §5.6); whether GitHub's runner has it is not known before the owner pushes (LIM-16). | LIM-06 | **Empirical, bounded evidence only.** A clean campaign means that the checkers found no violation in N valid runs of a stated schedule distribution, with the stated statistical bound and exposure (CONTRACT §12.3). | LIM-07 | **Narrow workloads.** Small tables, short transactions, no DDL during failover, no large objects, no COPY, no two-phase commit, no advisory locks, no temporary tables, no long-running transactions beyond P01. Isolation is checked for list-append transactions only. | DESIGN |
| LIM-08 | **Checker subset.** C3 reimplements a subset of Elle (list-append; G0, G1a, G1b, G1c, G-single, G-nonadjacent, G2-item, duplicates, incompatible order, internal); no rw-register version inference, no predicate anomalies. | LIM-10 | **Relationship to upstream testing.** Upstream runs deterministic end-to-end scenarios, pg_regress-family suites, TLA+ design models, and an internal chaos test ("Multiquake") whose scope is not public; external manual fault testing found and helped fix data loss in March 2026 (#777, #778).
